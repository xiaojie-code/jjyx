## 今天完成的

### 1. 后台管理系统资源加载问题

- 修了后台部署在 `/admin/` 下时 JS/CSS 资源 404 的问题。
- 原因是 Vite 打包路径没配对，页面会去 `/assets/` 找文件。
- 已改成 `/admin/assets/` 这种路径。
- 这部分已经提交并推送过一次。

### 2. 检查更新功能优化

- 查了下载失败的问题，发现之前配置的下载域名有证书问题，而且 CDN 返回了 `418`，所以手机端才一直提示网络异常。
- App 端下载逻辑做了增强：
  - 支持相对地址，比如 `/downloads/xxx.apk`
  - 下载失败提示更明确，比如证书异常、404、403、418
  - 下载完成会检查是不是 APK 文件，避免把错误页当安装包
  - 下载进度不会超过 100%
- 后台版本管理也加了校验：
  - 下载地址必须是 `.apk`
  - 文件大小必须是正整数
  - MD5 必须是 32 位
  - 新增“测试”按钮，可以直接打开下载地址验证
- 服务端支持 `PUBLIC_ORIGIN`，正式部署时可以把相对下载地址补成完整公网地址。

### 3. 商城模块开发

- 去掉了商城页原来的“测试中，暂未开放”。
- 优化了视频展示样式，改成“产品介绍 + 副标题 + 圆角视频卡片”。
- 新增商品宫格：
  - 2 列布局
  - 6 个商品
  - 图片来自 `server/uploads/shangcheng`
  - 商品名、卖点、价格都排好了
- 商品点击体验也补了：
  - 点击时有轻微按压效果
  - 有水波反馈
  - 点击后提示“测试中，敬请期待”

### 4. 本地服务重新启动

- 后端、后台、Flutter Web 都重新启动过。
- `localhost:3200` 之前跑的是旧 Flutter Web 进程，所以页面没更新；后来已经停掉旧进程并重新启动。

## 当前可能存在的问题

1. **本地和正式环境地址容易混**

   本地开发现在用 `192.168.31.73:3001`，不要误用服务器 IP。

2. **检查更新的数据库里还有旧下载地址**

   当前本地接口返回过 `192.168.31.74` 的旧 APK 地址，后面测试更新前要改掉。

3. **Flutter Web 有时会看到旧页面**

   如果 `localhost:3200` 页面没变，大概率是旧 Web 进程没重启，或者浏览器缓存没刷。处理方式是重启 Web 服务 + `Ctrl + F5`。

4. **商城图片依赖后端静态资源**

   App 要指向正确的 `API_BASE_URL`，否则商品图片会加载失败。

5. **当前有未提交改动**

   今天检查更新和商城模块的代码还没提交，后面确认没问题后再统一提交。
