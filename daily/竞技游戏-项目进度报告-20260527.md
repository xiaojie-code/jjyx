### 2. 修了聊天实时消息问题

之前的问题是：用户A给用户7发消息，用户7这边不能实时收到，也没有消息角标。

今天做了这些处理：

- 后端聊天网关支持同一个用户多个 Socket 连接。
- 用户断开连接时，只移除当前 socket，不再误删整个用户在线状态。
- App 端 Socket 会根据当前登录 token 判断是否需要重连。
- 退出登录时会主动断开旧 Socket，避免切账号后还挂着旧连接。
- 底部消息角标继续跟随 Socket 新消息更新。

## 当前可能存在的问题

### 1. 手机端网络地址问题

Web 调试时 `localhost` 能用，但打包到手机后，手机里的 `localhost` 指的是手机自己，不是电脑后端。

所以真机测试前，需要改成局域网 IP、测试服务器地址，或者做环境配置。

### 2. Socket 真机稳定性还要测

今天修了 Web 场景下的 Socket 身份和在线状态问题，但手机端还要继续测：

- App 切后台后会不会断线。
- 重新打开 App 后能不能自动重连。
- 弱网下消息会不会丢。
- 离线消息和角标是否正确。

### 3. JSBridge 还有接口对不齐风险

目前 App 侧 JSBridge 已经有基础通信，但游戏里的扣积分、买皮肤、结算上报还需要跟后端接口逐个对齐。

这里如果不联调，H5 游戏能打开，不代表真正能结算和同步余额。

### 4. 赛马接口可能还不完整

App 端常量里有赛马 `join`、`start` 相关接口，但后端目前主要看到创建房间、投注、结算、查询房间。

后续做赛马联机时，要把前后端接口重新对一遍。

### 5. 矩阵推广还有边界场景

矩阵核心逻辑已经有了，但多层级联、同一用户多次入位、历史旧数据、启动资金为 0 等情况还要继续测。

### 6. 打包权限和资源要单独检查

头像、图片、WebView、网络请求、文件上传这些功能，在 Web 上能跑，不代表手机包里一定没问题。

后面打包前要专门检查安卓/iOS 权限和资源路径。

## 下一步建议

1. 先把聊天模块在手机端真机跑一轮。
2. 再把 App 接口地址改成可配置，解决打包后不能访问后端的问题。
3. 接着做 H5 游戏 JSBridge 联调，优先测扣积分、结算、余额同步。
4. 最后走完整打包流程，整理 APK、iOS 包和下载页。

总体来说，项目已经不是从零开始了，核心东西都在。现在最重要的是把“能跑”变成“真机上稳定能用”。
