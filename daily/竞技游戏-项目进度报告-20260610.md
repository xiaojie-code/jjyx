# 竞技游戏平台项目进度报告

**日期：2026-06-10**

## 当前项目进度

项目现在还是 App、后端、后台管理、H5/WebGL 游戏几块一起推进。

整体功能已经比较完整了，登录注册、聊天、联系人、商城、游戏大厅、充值提现、后台管理、APK 打包安装这些主流程都已经能跑。现在主要不是从 0 做功能，而是在做细节优化、真机测试和积分逻辑收口。

今天重点还是围绕游戏和 App 体验在改：大逃杀结算、实况钓鱼积分降级、蛇蛇大作战皮肤保存、幸运转盘、商城预售、登录页品牌图这些都做了一轮调整。

## 今日完成内容

- 大逃杀结算逻辑重新梳理并调整了一轮。
  - 被杀手抓到的用户，本局投入积分直接扣掉，不返还。
  - 没被抓到的用户，按自己投入积分占未被抓到用户总投入的比例，去分被抓到房间的积分。
  - 用户最终拿到的是自己的投入流水返还，加上按比例分到的收益。
  - 修了“明明下注了，结算却显示没有下注”的问题方向。

- 大逃杀前端文案和下注体验也调整了。
  - “投入金币”改成了“投入积分”。
  - 可选积分按 100、500、1000、3000、5000、1w 这套处理。
  - 默认投入积分改成 100。
  - 删除了“获胜玩家 +xxx”这类多余显示。
  - 去掉了“真实玩家”之类不该给用户看的话。
  - 用户最后 3 秒没下注时，系统会默认随机选房间下注 100 积分。

- 实况钓鱼积分做了降级。
  - 鱼具店、鱼市场等商品价格按 100 变 10、1000 变 100 这种比例降下来了。
  - 钓上来的鱼收益也同步降级。
  - 技巧、饵料、抄网等升级所需积分也做了降低，递增逻辑还保留。

- 蛇蛇大作战做了皮肤相关优化。
  - 皮肤购买后退出再进丢失的问题做了处理。
  - 皮肤价格统一降级，大于等于 1000 的价格按除以 10 处理。

- 幸运转盘做了一轮优化。
  - 奖品全名补齐：沧恒云芯智能 AI 机器人、云芯智慧大屏 100 寸、云芯大屏对开门冰箱。
  - 转盘页面做大了一点，奖品名字更容易放下。
  - 指针和中奖弹窗重新美化，看起来更清楚。
  - 转盘整体样式也重新收了一版。

- 商城模块做了预售体验。
  - 用户点“订购”后，现在弹窗展示商品图。
  - 数量加减控件默认是 0，并且置灰不能操作。
  - 底部显示“预售中”。
  - 产品视频默认静音。

- 积分合成页面新增了两个预留入口。
  - 新增“合成金币”“合成银币”按钮。
  - 数量默认 0，加减置灰，暂时不能操作。

- 充值短信功能做了设计和接口接入方向。
  - 后台充值管理里的“已发码”调整为发送激活码短信的功能方向。
  - 点击后弹窗填写激活码，手机号和姓名自动带入。
  - 发送前需要校验内容不能为空。
  - 短信接口配置也已经开始接入，`SMS_APPCODE` 需要放到环境配置里。

- 登录页品牌图已经加上。
  - 把蓝色沧恒云芯图标放到了 App 登录页“沧恒云芯智能平台”标题上面。
  - 登录页单文件检查已经通过。

- 今天也多次做了服务启动、Web 测试、APK 打包安装相关操作。

- 实况钓鱼已经完成一轮积分数值降级。
- 蛇蛇大作战已经做了皮肤保存和价格降级。
- 幸运转盘已经有抽奖次数、奖品记录、中奖弹窗和基础样式。

## 未完成的内容

- 大逃杀还需要继续真机多跑几局，重点确认下注、默认下注、被抓、未被抓、收益分配、余额刷新都完全对。
- 大逃杀的结算公式虽然已经按新规则调整，但还需要拿真实数据对账，避免小数、四舍五入、多人同局时出现偏差。
- 赛马中文显示和资源问题还没有彻底收口，后面还要继续查资源包。
- 实况钓鱼虽然积分数值降了，但金币和 App 积分是否所有入口都完全同步，还需要继续压测。
- 蛇蛇大作战皮肤保存需要继续真机复测，确认退出重进后一定不丢。
- 商城目前还是预售展示，没有真正的订单、支付、收货地址、订单管理。
- 合成金币、合成银币目前只是预留入口，还没有正式开放合成功能。
- 短信发送功能还需要继续补环境配置、接口测试、失败提示和后台操作日志。
- 厂商推送还没完全落地，后面还要接各品牌 SDK 和密钥。
- APK 每次打包前还要确认接口地址，是局域网测试地址还是正式服务器地址。

## 当前项目可能存在的问题

- 当前工作区改动很多，文件比较杂，后面继续改的时候要注意不要覆盖之前已经调好的内容。
- `app/video/video(9).mp4` 现在是删除状态，商城视频在 Web 端会有 404；如果要展示视频，需要把资源补回来。
- Web 控制台里还看到过 `assets/assets/shangcheng/bl.png` 这类资源 404，说明有些图片路径或资源声明还要再查一下。
- 有些游戏是打包产物，改起来不如普通代码好维护，后续大改玩法会比较费时间。
- 游戏里的“金币/积分/收益/流水”概念还要继续统一，不然用户看到的数和后台结算容易对不上。
- 本地服务、Web 端、手机端、APK 包之间环境切换比较频繁，接口地址配错就会出现看起来很怪的问题。
- Gradle 打包偶尔会卡，后面还是优先用已经记录过的离线打包脚本。
- 短信、推送这类外部服务依赖配置和网络环境，不能只看代码，还要实际发一遍、收一遍。

## 下一步建议

建议接下来先别铺太多新功能，先把今天改过的重点功能真机跑稳。

1. 先集中测大逃杀，拿几组不同下注数据对账。
2. 再测蛇蛇皮肤购买、退出、重进是否稳定保存。
3. 接着测实况钓鱼买卖、升级、收益是否都按降级后的积分走。
4. 然后补商城缺失的视频和图片资源，避免 Web/App 控制台一直报 404。
5. 最后继续推进短信激活码发送、商城订单、合成金币/银币这些后续功能。

简单说，项目现在已经能跑，今天主要是在把用户能直接看到、能直接算钱的地方往稳里修。下一步重点就是对账、真机复测、补资源和整理环境配置。
